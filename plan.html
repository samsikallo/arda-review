II

The order of the work

Ruling C65 chose breadth over depth. Forty‑six halls at the same honest level looks like a book; one magnificent hall among forty‑five plain ones looks broken. The risk is stated rather than hidden — nothing is finished until pass three.

Pass one

Make the skeleton real

Generate hall spreads when the site is built, as the 582 entity routes already are. Reuse the emitter that works; do not fork it. 404.html proved the method today — it went from 8/34 to 33/34 by importing that emitter rather than copying it.

Four things stop being faults at once: the page a reader gets is the page in git, a guard can check it, it works with JavaScript off, and the leaf count stops changing between loads.

skeleton band  8/46 in git  →  40/40 in git

Pass two

The apparatus, where a record exists

The apparatus band sits at 1/46 and rises only as far as real records reach. Each feature needs its dataset, its register row and its declaration first, or it is invented scholarship. Two records are already built: 1,212 errata and the device dossiers.

One feature may never be built at all. No per‑entity gloss record exists, and the prototype’s own corrections turned out to be cosmetic pairs, inconsistent about which reading is older. They are not evidence of anything.

Pass three

The five at zero, and the declared ceilings

Two of the five already work on the entity side — 670 manicules stand on the 335 routes with an unresolved reading, and the struck reading now carries the whole errata register. A hall gets them only where a hall has the same kind of claim. Where it does not, the ceiling is declared and counted, not quietly skipped.

III

What had to be fixed first

Four agents working independently found the same root cause on the same day. One CSS property — height — was never reset in the narrow‑screen block, so the board stayed 231 pixels tall on a phone and a whole record was asked to fit inside it.

Measured across 340 validated cells at four widths: 83 of 85 pages scrolled sideways at 768px and below, and not one of the 582 entity routes was correct below 1024px. The proof was sitting in the file the whole time — the volume contents pages were the only ones granted that reset, and the only ones that survived a phone.

Measured separately, and just as invisible to every visual review: the page‑turn control — the archive’s primary navigation — is 28 pixels wide and fails the minimum touch target on every page at every width.

What this plan refuses to promise

  • 105 device corners stay blank, and that is the correct outcome. A device the lore cannot support is worse than a blank corner. The ceiling is 113 of 218 subjects — 51.8% — because 43 are landforms that cannot bear arms, 27 are hobbit, and 26 are real bearers the corpus simply never describes.
  • 6,800 real changes stand in git with no stated reason — 85% of everything that ever changed. No reason will be inferred for them, because a recovered reason is a guess about why, and a wrong one produces an erratum that is verbatim and false. The register publishes its own denominator instead.
  • The apparatus will not reach 46/46. It reaches as far as the records reach. The ceilings above are measured limits, not targets to be beaten.
  • There is no differencing anywhere in Tolkien — no cadency, no brisures, no abatements across 33 of his own files. Devices pass down unchanged. Any scheme that assumed otherwise was building heraldry he never wrote.

The working document this page summarises is CODEX_TRANSFORMATION.md, which the agents execute from. Where a number here will rot, that file gives the command that reproduces it instead. The reference object is the last spread in codex-proto.html, which is never edited.
